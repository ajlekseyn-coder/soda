# Калибровка читаемости на Soda и Laravel

Правила должны убирать скрытые операции и лишнее разнесение поведения, сохраняя
понятный код на месте. Числа не воспроизводят вкус автора. Практический ориентир —
видимые изменения состояния, понятный сценарий вызова, concern у владельца и
отсутствие обязательных обёрток для простой структуры данных.

[DHH описывает concerns](https://signalvnoise.com/posts/3372-put-chubby-models-on-a-diet-with-concerns)
как способ организовать поведение владельца, включая concern для одного класса.
Его [Pattern vision](https://signalvnoise.com/posts/3341-pattern-vision) предостерегает
от назначения паттернов заранее. Это основания нашей интерпретации, а не участие,
одобрение авторов или обещание получить их стиль автоматически. Методы Laravel
ниже — проверяемые примеры из кодовой базы проекта, а не утверждение, что каждый
из них лично написал Taylor Otwell.

## Изменения стандартной политики

| Конструкция | Стандартная политика | Строгий режим |
|---|---|---|
| Литерал в ключе массива или обращении по ключу | Не считается повторяющимся значением | `NoRepeatedStringLiterals(includeArrayKeys: true)` |
| Прямой `return $cache ??= calculate()` | Разрешён со стабильной целью и без вложенных присваиваний | `allowLazyInitialization: false` |
| Прямой `return $this->cache = calculate()` | Разрешено одно именованное обновление владельца | `allowOwnerStateReturn: false` |
| Arrow callback с обновлением `$this` в `match`/тернарных ветках | Разрешён; записи в условиях, аргументах и локальных переменных проверяются | `allowArrowStateUpdates: false` |
| Ведущая нормализация того же входа через известные scalar/string операции | Разрешена один раз на параметр | `NoReassignedParameters(allowInputNormalization: false)` |
| Цикл модулей | Показывает реальный замкнутый путь, типы и декларации, подтверждающие рёбра | Границы задаются `modules` |

Обычные цепочки присваиваний остаются запрещёнными. Присваивания по ссылке,
динамические цели, чужой объект/статическое хранилище другого именованного класса,
скрытые локальные записи и вложенные записи в значении не получают исключения
для обновления владельца. Наличие callback не доказывает, что его результат
игнорируется; исключение определяет читаемую синтаксическую форму.

Нормализация не распространяется на произвольные `normalize()` и вызовы методов,
не разрешает подмену входом другого параметра или новое значение без исходного
входа. Известная функция в том же исходнике, например `App\trim`, не получает
исключение встроенной функции. Межфайловое и динамическое переопределение функций,
runtime purity и сохранение предметного смысла входа не выводятся.

## Доказательства в собственной кодовой базе

- `FactCatalog::all` и `ExpressionCheck::compiled`: прямое ленивое кеширование.
- `FactoryHookContracts::isRequired`: нормализация именованных идентификаторов.
- `ClassBehaviorFacts`: повторяющиеся поля компактной структуры фактов.
- `NoDependencyCycles`: вывод рёбер, а не только списка компоненты.

[ReadabilityPolicyCalibrationTest](../../../tests/unit/ReadabilityPolicyCalibrationTest.php)
проверяет настоящие исходники Soda стандартным и строгим режимами.
[PracticalDesignTest](../../../tests/unit/PracticalDesignTest.php) проверяет concern
одного владельца, fluent API, readonly-данные и остальные практические примеры
четырнадцатью выбранными стандартными правилами дизайна и читаемости. Остальные
строгие политики всей системы этим тестом не проверяются.

С одинаковой конфигурацией и областью `src` собственный отчёт изменился
с **303 до 85 сообщений**. По идентификаторам групп новых сообщений нет;
изменились доказательства цикла и число/строки оставшихся повторов. Не менялись
пороги ради этого результата и не отключались правила. Оставшиеся 85 — сигналы
для разбора, а не объявленные дефекты или обещание обязательного рефакторинга.

## Неизменённые методы Laravel

[LaravelReadabilityPolicyTest](../../../tests/unit/LaravelReadabilityPolicyTest.php)
проверяет пять методов из Laravel Prompts v0.3.21 и Sanctum v4.3.3:

- `AutoCompletePrompt::matches`: возврат результата с заполнением кеша.
- `ConfirmPrompt::__construct`: краткий callback состояния через `match`.
- `Themes::theme`: явное обновление именованного статического состояния.
- `DataTablePrompt::filteredRows`: ветки заполнения кеша фильтрации.
- `HasApiTokens::generateTokenString`: локальное присваивание внутри аргумента
  возвращаемого вызова остаётся замечанием.

В стандартном режиме — **1 замечание**, в строгом — **8**. Остаток можно вынести
в локальную подготовку перед `return`, сохранив однократное вычисление случайного
значения и порядок вызовов. Сам по себе он не означает ошибку генерации токена.

Извлечённые методы сохраняют синтаксис; изменены только окружающие имена классов,
imports и форматирование файла фикстуры. Кеши и callback'и не переписаны для
получения зелёного теста. [Provenance](../../../tests/fixtures/readability/laravel-methods.json)
содержит версии, source commit, SHA-256 исходных файлов и канонического текста
каждого метода. Тест сравнивает хеши с зафиксированным реестром исходников.
[MIT-лицензия](../../../tests/fixtures/readability/LICENSE.laravel) сохранена.
Это синтаксические фикстуры, не исполняемые модели Laravel.

## Прогон на 179 зафиксированных PHP-файлах

Сравнивались только семь правил: повторяющиеся строки, присваивания в `return`,
переприсваивание параметров, последовательные локальные присваивания, цепочки
присваиваний, число инструкций (20), когнитивная сложность (15).
Другие 91 правило стандартного набора этим прогоном не оценивались.

| Пакет | PHP-файлов | Строгая политика | Контекстная политика |
|---|---:|---:|---:|
| laravel/prompts v0.3.21 | 86 | 86 | 62 |
| laravel/sanctum v4.3.3 | 20 | 6 | 5 |
| laravel/scout v11.5.0 | 40 | 71 | 45 |
| laravel/pail v1.2.7 | 15 | 18 | 10 |
| laravel/sail v1.66.0 | 5 | 15 | 12 |
| laravel/serializable-closure v2.0.15 | 13 | 80 | 61 |
| Всего | 179 | 276 | 195 |

81 сообщение снято явными исключениями политики: 62 группы повторов строк и
19 возвращаемых присваиваний. Утверждение, что все снятые сообщения были дефектами
детектора или все оставшиеся 195 являются дефектами кода, из этого не следует.
Тесты с положительными/отрицательными примерами обосновывают конкретные исключения;
счётчики корпуса обнаруживают изменения политики, но не измеряют глобальную
точность рекомендаций. Метрики размера и сложности сохраняются как поводы для
ревью, без автоматического извлечения объектов.

[results.json](results.json) содержит версии, commits и счётчики по правилам.
SHA-256 всех файлов проверяются по
[исходному manifest](../laravel-audit/packages.json). Исторический полный реестр
аудита не переписывается под новые исключения и не объявляется текущим отчётом.

Для воспроизведения подготовьте JSON с отображением всех шести имён пакетов на
корни их точных установленных версий; внешние исходники тест только читает:

```sh
SODA_READABILITY_CORPUS=/absolute/corpus-roots.json \
  vendor/bin/phpunit --filter ReadabilityCorpusTest
```

Без установленного корпуса этот интеграционный тест явно пропускается.
Сохранённые методные фикстуры и пограничные тесты запускаются без внешних пакетов.
